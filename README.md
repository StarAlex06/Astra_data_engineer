# Building Materials ETL

ETL-проект для загрузки продаж строительных материалов и недельных макропоказателей за 2019–2024 годы в SQLite. Нужен Python 3.10 или новее; сторонние пакеты не требуются. Проектные решения и схема описаны в [TASK.MD](TASK.MD).

## Структура

- `building_materials_transactions.csv` — исходные продажи.
- `macro_drivers_weekly.csv` — недельные макропоказатели.
- `data_dictionary_materials.csv` — словарь полей.
- `etl.py` — извлечение, валидация, трансформация, загрузка.
- `TASK.MD` — анализ источников и обоснование архитектуры.
- `tests/test_etl.py` — базовые автоматические проверки.
- `data/warehouse.sqlite` — локальная база, создаётся при запуске и не хранится в репозитории.

## Схема хранилища

`fact_transactions` хранит показатели продаж и ключи измерений: календаря (`dim_date`), региона (`dim_region`), товара (`dim_product`), канала (`dim_channel`) и типа клиента (`dim_customer_type`). Таблица `macro_weekly` хранит показатели по неделям, а `rejected_rows` — строки, которые не прошли проверку, с причинами отказа.

## Быстрый запуск

Из корня проекта:

```powershell
python etl.py
```

По умолчанию создается `data/warehouse.sqlite`. Для других файлов:

```powershell
python etl.py --transactions path/to/sales.csv --macro path/to/macro.csv --database data/warehouse.sqlite
```

Скрипт печатает сводку в JSON. Его можно запускать повторно: одинаковые строки не дублируются. Ключ строки строится по имени файла и её номеру, поэтому для обновления исторических данных сохраняйте имя файла и порядок уже загруженных строк. Базу можно открыть в DB Browser for SQLite.

## Проверки

```powershell
python -m unittest discover -s tests -v
```

При критической ошибке SQLite отменяет транзакцию. Некорректные строки записываются в `rejected_rows` вместе с исходной записью и причиной. Бизнес-правила и ограничения ключа описаны в `TASK.MD`.
